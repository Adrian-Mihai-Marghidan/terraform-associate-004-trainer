# Privacy and sensitive reports

This educational project runs local Terraform exercises. Its simulator integration requires no Azure account or credentials. Personal records and runtime infrastructure belong in each learner's ignored local files and separate private backup.

Keep credentials, state, plans, simulator stores, private assessments, personal notes, and employer information out of public issues, pull requests, screenshots, and attachments. Public-file checks inspect known artifact paths and home paths; they do not detect every possible secret or personal detail.

For a nonsensitive bug, provide a minimal fictional reproduction as described in [CONTRIBUTING.md](CONTRIBUTING.md).
For a security issue, use GitHub's private vulnerability reporting when enabled for the published repository. Until a private channel is configured, share only a sanitized problem description and arrange private reporting before transmitting sensitive material. Never post an actual credential to demonstrate a defect.

The maintainer will review issues as project time permits; no response-time or production-support commitment is made. Public reporting availability must be configured during [publication preparation](docs/PORTFOLIO.md#publication-preparation).
